# Data Documentation

This document describes the training data used by the sentiment analysis
application, how it is versioned with DVC, and how code commits map to
dataset versions.

## 1. Source

| Field | Value |
|-------|-------|
| Dataset | **IMDB Movie Reviews** (`stanfordnlp/imdb` on Hugging Face) |
| Source URL | https://huggingface.co/datasets/stanfordnlp/imdb |
| License | As stated on the Hugging Face dataset card (originally Maas et al., 2011, ACL). |
| Raw location | `data/raw/imdb_raw.csv` |
| Storage | DVC remote **`myazure`** (Azure Blob Storage) |
| Task | Binary sentiment classification |
| Schema | `text` (string), `label` (int: `0` = negative, `1` = positive) |

Raw data is generated by `scripts/make_raw.py`, which loads the IMDB corpus
with `datasets.load_dataset("stanfordnlp/imdb")` (train + test splits), samples
a deterministic subset, and writes a single CSV with columns `text`,`label`.
Both splits of IMDB are inherently ~50/50 positive/negative, so the data is
naturally class-balanced (no manual rebalancing is applied).

> Raw data is **not** committed to Git. Only the small `.dvc` pointer files
> live in the repository; the actual files live in the DVC Azure remote.
> To work with the data you must `dvc pull` (see §4). A teammate who clones
> the repo must set their own SAS token in `.dvc/config.local` first.

## 2. Dataset versions

Two versions are maintained. The "DVC pointer" column is the `md5` stored in
`data/raw/imdb_raw.csv.dvc` at that commit — it is the immutable fingerprint of
the raw file content (and therefore of the dataset version).

| Version | Commit | DVC pointer (`data/raw/imdb_raw.csv.dvc`) | Raw rows | Processed train/val/test | Description |
|---------|--------|-------------------------------------------|----------|--------------------------|-------------|
| **v1** | `bb66071` | `md5: 386c71678095069c82a39648b39cf4c4` (size 9.28 MB) | 7000 | 4994 / 1000 / 1000 | First usable dataset, used for the baseline model. |
| **v2** | `b0f2082` | `md5: 8fc4498fad8451c4091cca0a4ff595de` (size 18.50 MB) | 14000 | 11979 / 1000 / 1000 | Larger real sample + deterministic light augmentation. |

Notes on the commits:
- `bb66071` ("feat(data): wire DVC pipeline for IMDB v1 dataset") is the commit
  that minted and tracked **v1**. It was merged into `dev` via PR #4
  (merge commit `c7e42cc`).
- `b0f2082` ("feat(data): dataset v2 — new seed, 10k base + light augmentation")
  is the commit that minted and tracked **v2**. A follow-up `ad19c46` only
  fixed ruff lint/format in `make_raw.py` and does **not** change the data.
  v2 was merged into `dev` via PR #7.
- Both dataset versions remain in the Azure remote, so either can be restored
  with `git checkout <commit> && dvc pull`.

## 3. v1 → v2 changes

What changed between the two versions:

- **Random seed**: `42` → `1337`. v2 is an independent random sample of real
  IMDB rows, not a superset of v1.
- **Base (real) sample size**: `7000` → `10000` rows.
- **Added synthetic augmented samples**: `+4000` rows (40% of the base,
  `AUG_FRACTION = 0.4`). These are produced by `scripts/make_raw.py` with
  **deterministic, label-preserving** light augmentation:
  - character dropout (drop one char from ~3%-prob long tokens), and
  - ending-punctuation variation (`.` / `!` / `?` shuffled),
  - *(WordNet synonym replacement is also coded but is **skipped in offline
    environments without the NLTK `wordnet` corpus**; re-running `make_raw.py`
    where NLTK corpora are available will additionally apply synonym swaps. The
    v2 file in Azure was generated offline, so only the first two techniques
    actually ran.)*
- **No outlier removal** beyond dropping exact duplicate rows (see cleaning
  below). No manual class rebalancing — both versions stay ~50/50 because IMDB
  is balanced by construction.
- **Same cleaning & split pipeline** (`src/sentiment_analyzer/data/prepare.py`,
  unchanged between versions): strip HTML `<br />`, normalize whitespace, cast
  `label` to `int`, drop exact duplicates, then a stratified split with
  `N_VAL = 1000`, `N_TEST = 1000` (the remainder becomes `train`).

Net effect: v2 trains on ~2.4x more rows (11979 vs 4994) drawn from a fresh
seed, with a small synthetic-augmentation tail, while keeping the identical
val/test holdouts (1000 each) for comparable evaluation.

## 4. Reproducing / pulling a dataset version

```bash
# --- Teammate: pull an existing version ---
git checkout <commit-sha>        # e.g. bb66071 (v1) or b0f2082 (v2)
uv sync --all-groups
# set YOUR SAS token locally (never commit it):
dvc remote modify --local myazure account_name wut2026
dvc remote modify --local myazure sas_token "sp=...&sig=..."
uv run dvc pull                  # restores data/raw/imdb_raw.csv + data/processed/

# --- Author: mint and publish a new version ---
uv run python scripts/make_raw.py          # regenerates data/raw/imdb_raw.csv
uv run dvc add data/raw/imdb_raw.csv       # updates data/raw/imdb_raw.csv.dvc
uv run dvc repro prepare                   # regenerates data/processed/
uv run dvc push                            # uploads to Azure remote myazure
git add data/raw/imdb_raw.csv.dvc dvc.lock scripts/make_raw.py ...
git commit -m "data: add vX dataset"
```

> The IMDB download uses the Hugging Face mirror
> (`HF_ENDPOINT=https://hf-mirror.com`, set inside `make_raw.py`) for reliable
> access from the CN region.

## 5. Processed data

The `prepare` DVC stage turns the raw CSV into the splits consumed by training:

```
data/raw/imdb_raw.csv   ->  data/processed/train.csv
                          data/processed/val.csv
                          data/processed/test.csv
                          data/processed/metadata.json
```

`metadata.json` records the active version (`dataset_version`, `raw_seed`,
`n_base`, `n_augmented`, split sizes, and label distribution) so every training
run can be traced back to the exact dataset version it used.

Run it with:

```bash
uv run dvc repro prepare
# or directly:
uv run python -m sentiment_analyzer.data.prepare --raw data/raw --out data/processed
```
